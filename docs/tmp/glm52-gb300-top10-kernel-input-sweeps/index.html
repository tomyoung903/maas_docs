Operator boundary

CUDA events bracket the production SGLang/FlashInfer callable. It includes auxiliary GPU work and output preparation, so it is intentionally broader than one leaf.

Routing diversity dominates the middle of the curve. At M=192, the exact first GEMM takes 63.65 µs with 8 active experts and 123.60 µs with 256. By M=512, all four lines converge near 141–146 µs because token work, rather than sparse expert occupancy, owns the launch.

K2

TRT-LLM FP8 selected-token attention

Sparse MLA attention

−45.9%S 2048 → 1024 at M=192
Measured contractM rows · selected tokens S · 8 local heads · head width 576

Selected-token count is the strongest measured runtime knob. At M=192, lowering S from 2048 to 1024 reduces exact-leaf residency from 58.00 to 31.39 µs. Holding S=2048, context lengths from 4K to 1M remain within 0.08 µs because the sparse kernel scans the selected table, not the full context.

Configuration readingS=1024 is the highest-value candidate, but it changes model semantics and requires accuracy testing. The exact top-ten leaf dispatches when M × S reaches 24,576; smaller products select another implementation.

2.05 µsM=192 · W=6144

The exact UE8M0 quantizer has a strong launch floor: all five widths remain near 1.6–2.1 µs at M=192. At M=512, W=6144 reaches 3.18 µs and about 3.0 TB/s of modeled useful traffic, still far below the attention and routed-MoE leaves.

Configuration readingWidth is architectural rather than a runtime knob. Keep K5 in the cost model, but prioritize K2, K8, and fused MoE before investing in quantizer-specific tuning for this load shape.

12.9% → 31.9%modeled MFU · M 192 → 512

This is the clearest batching win. Exact-leaf latency rises only 8.0%, from 9.57 µs at M=192 to 10.34 µs at M=512, while modeled useful FP8 MFU rises from 12.9% to 31.9%. The non-monotonic bends come from DeepGEMM template changes, not measurement gaps.

Configuration readingLarger verification groups amortize this projection well. The limiting question is whether the faster QKV-A work offsets the much steeper K2, K8, and communication growth at the same M.

K8

Selected-token index transformation

Decode page-table gather

−66.4%S 2048 → 1024 at M=512
Measured contractM rows · selected tokens S · context C · locality

The gather stays near a 5 µs floor at small M, then selected-token count and locality take over. At M=512, random S=2048 costs 26.40 µs while S=1024 costs 8.86 µs. At M=192, contiguous S=2048 is 5.06 µs versus 6.75 µs for random indices.

Configuration readingReducing DSA top-k benefits both K2 and K8. Reordering indices for locality is a separate implementation candidate only if semantic order can be restored cheaply and the full attention path preserves correctness.
