What moves between trees?

A projection splits into its real launches

A logical projection normally owns online BF16→FP8 quantization followed by GEMM. The operation tree keeps them together; this type tree places the quantizer under precision conversion and the GEMM under matrix compute.

What is absent?

No standalone dequantization kernel

No separately named dequantization launch appears among the 54 raw symbols. Conversion performed inside a grouped GEMM or epilogue remains fused into that launch; absence here does not prove that no conversion instructions execute.

03

Semantics

How to read this hierarchy

“Child of” means a more specific implementation type. It does not mean the child executes inside the parent in model order.

1

Broad type

Matrix, attention, quantization, normalization, routing, communication, or memory/control.

2

Subtype

For example dense linear projection, sparse MLA, BF16→FP8 quantization, or an MNNVL TP handoff.

3

Fine type

For example DeepGEMM, persistent FMHA, per-token group quantization, or a two-shot exchange.

4

Exact signature

Raw symbol plus provider, grid, block, registers, and shared-memory configuration. Original operation owners remain linked.

Timing

Overlap is visible, not silently subtracted

These are the non-zero pairwise overlaps between broad types. They explain why category active unions cannot be added to recover the root union.

Σ residency

Add every CUPTI start-to-end duration, even when intervals overlap.

∪ active

Merge overlapping intervals once on GPU 0.

Incremental

Root union minus the union after removing this subtree. This is timeline attribution, not isolated latency.

Overlap-covered

Part of this subtree’s union simultaneously covered by at least one event outside it.

05

Audit

Classification and reconciliation method

The taxonomy is deterministic and fail-closed: an unknown exact launch causes generation to stop.

  1. 01

    Start from audited ownership

    Read the 3,202-row GPU-0 ownership ledger produced by the original tree generator. Every row already has one semantic owner and exact raw launch evidence.

    source-derived
  2. 02

    Classify physical mechanism

    Use exact provider/name patterns plus the existing semantic operation only where a generic support symbol needs context, such as sparse-MLA workspace reset or graph setup.

    deterministic
  3. 03

    Split by exact launch signature

    A leaf is one raw symbol, provider, grid, block, register count, and static/dynamic shared-memory configuration. Same-symbol launches with different geometry become different leaves.

    59 leaves
  4. 04

    Recompute interval metrics

    Residency, same-GPU union, incremental union, and pairwise top-level overlap are recomputed directly from the original start/duration fields.

    nanosecond exact
  5. 05

    Reconcile to the source tree

    Event IDs, launch count, summed residency, and active union must match the operation tree exactly. No event is added, dropped, or counted twice.

    pass

Limits carried forward

  • The selected replay has no attributable output-token role.
  • Kernel type does not replace logical model ownership.
  • CUPTI duration is not isolated kernel arithmetic or verified dependency-critical-path time.
  • MFU and MBU remain intentionally absent from this selected-replay tree.
  • No separately named dequantization launch does not imply that fused kernels execute no conversion instructions.
