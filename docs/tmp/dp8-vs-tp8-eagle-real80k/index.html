One EAGLE verification cycle

1 · DraftThe EAGLE draft head proposes up to five continuation tokens from target-model hidden-state features.
2 · Target verifyThe target model evaluates the proposed chain together in one verification forward over six positions.
3 · Accept prefixTokens are accepted only until the first mismatch. Later draft tokens are discarded even if they happen to match.
4 · Bonus tokenThe target distribution samples the replacement/bonus token that guarantees exact target-model semantics.
5 · Commit and repeatAccepted target KV state is committed; rejected speculative state is not. The next draft cycle begins from the committed state.

Across all requests, DP8 completed 19,200 tokens in 7,981 verification passes; no-DP used 8,097. EAGLE therefore emitted about 2.4 final tokens per expensive target verification in both arms.

Validity and evidence

  • 32 distinct real conversation bodies; unique natural identifiers force immediate radix-prefix divergence.
  • DP8: 32 Finish records, 19,200 completion tokens, 0 cached tokens.
  • No-DP: 32 Finish records, 19,200 completion tokens, 0 cached tokens.
  • Both arms: same nodes, image, TP8, EAGLE 5-step/6-draft configuration, memory fraction 0.90, and NCCL fallback.
  • Small unavoidable difference: the no-DP archive header carries a cold-replay nonce because the external Mooncake content store survives pod deletion.

Rejected runs

  1. Full Nsight graph-node run: all requests failed after profiler overhead triggered the 300-second decoder watchdog.
  2. Forked-history draft: shared prefixes produced cache hits.
  3. First no-DP replay: external Mooncake content cache produced cross-arm hits.

Raw private prompt text is intentionally excluded. Local evidence files include benchmark JSONL, complete decoder Finish metadata, workload hashes, and rejected-run logs.
