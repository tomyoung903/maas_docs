GLM-5.2 PP8: 18 Minutes of Real One-Token Prefill Traffic

An evidence-backed analysis of 4,810 completed requests from the filtered request stream on eight H200 GPUs. The report separates queue-free internal TTFT from client TTFT, and separates cached prompt throughput from the uncached tokens that actually required new model work.

Main finding. In the last ten complete one-minute bins, total prompt throughput ranged from 9.38M to 15.66M tokens/min, while uncached throughput stayed between 2.02M and 2.25M tokens/min. Cache reuse changed the amount of prompt history served, but the new-token processing rate remained much tighter.

Cache

High token-weighted reuse

The weighted hit rate was 81.38%, versus a 64.55% mean across requests. Longer requests were more heavily cached, so token-weighted and request-mean ratios answer different questions.

Saturation

Client TTFT was queue-dominated

The replay held up to 80 requests in flight, and the public end-of-minute samples contained as many as 77 queued requests. Mean queue time was 85.18% of mean client TTFT, so these client latencies describe saturated service.

Context-dependent work

Uncached length tracks service time

Uncached tokens and internal TTFT had Pearson correlation 0.930. Requests with 1–1K uncached tokens had 1.773 s P50; requests above 64K had 4.564 s P50.

Scope. This is a valid analysis of the 4,810 durable completed rows, not a claim that the planned 55-minute run completed. They are a contiguous source-order prefix, ordinals 1–4,810. The server stopped at 06:23:44 UTC; 80 later issued requests, ordinals 4,811–4,890, are right-censored and excluded.

Plain-language interpretation: if a request’s lower bound is above zero, that request definitely read from L2. The test intentionally generated one token per request so every successful response is a prefill-first-token measurement and no TPOT interpretation is possible.

Evidence Boundary and Reproducibility

The public sidecar contains aggregates plus privacy-safe request ordinals and mathematical L2 attribution bounds. The sealed private artifacts retain request IDs, the canonical per-request join, and the exact formal server-log slice.

  • 4,810 unique durable client rows joined to 4,810 structured server finishes
  • Accepted rows are contiguous source ordinals 1–4,810 with no gaps
  • 4,810 exact internal-TTFT timestamp pairs and ordered PP0 cross-checks
  • 1,096 / 1,096 prompt-counter checkpoints match unique request-prefix sums
  • 1,096 / 1,096 device-plus-host cached counters match the same request prefixes
  • 4,810 HTTP 200 responses with exactly one completion token
  • Zero decode-batch lines in the measured formal log window
  • 4,805 / 4,810 completed rows have full PP0–PP7 timing evidence
  • Source corpus and seven postmortem payloads passed SHA-256 verification
  • 80 later issued rows, ordinals 4,811–4,890, are right-censored and excluded from all completed-prefix statistics
