先建立正确的心智模型

把模型与采样规则分开看。 GLM-5.2 检查点的第 78 层产生草稿 logits，进而形成草稿分布 q。这个开关不会重新训练该层、修改其权重，也不会让 logits 本身变得更准确。它改变的是：SGLang 如何从 q 中抽取候选、哪些概率信息会传入目标模型验证，以及验证器如何接受或校正候选。

推测解码究竟想节省什么

普通自回归解码每生成一个新 token，都要运行一次昂贵的 78 层目标模型。推测解码先让便宜的单层 MTP 辅助模型提出一条短候选链，再让目标模型一次性验证整条链。目标模型接受最长的有效前缀，并在边界处补上一个由目标分布采样得到的奖励 token。因此，接受的草稿 token 越多，一次目标模型验证就能摊薄到越多输出 token 上。

1低成本起草

第 78 层循环运行，依次提出 d1 到 d5。

2批量验证

完整目标模型通过一次批处理前向计算评估整条候选链。

3接受前缀

遇到第一个被拒绝的草稿 token 时停止；后续候选都依赖这个已被拒绝的前缀。

4校正并继续

目标模型给出一个分布正确的边界 token，然后开始下一轮起草。

接受长度不等于严格草稿接受数。 SGLang 的 avg_spec_accept_length 包含目标模型补上的一个奖励 token。在每轮提出 5 个候选时，显示接受长度 3.8，表示平均约有 2.8 个草稿 token 被接受，再加 1 个奖励 token；并不是接受了 3.8 个草稿 token。

这个开关究竟改变什么

令 p 表示经过温度与请求过滤后的目标模型采样分布，q 表示 MTP 草稿模型在同一词表上的候选分布。核心区别在于：验证器是看到完整的 q，还是把已选中的草稿 token 当成概率为 1 的点质量分布。

开关关闭 · 仅目标分布路径

Argmax 被折叠成点质量分布

  1. EAGLE top-k=1 选择草稿模型的 argmax token d。
  2. 验证器实际使用 qδ：d 的概率为 1，其余 token 的概率为 0。
  3. 该候选以 p(d) 的概率通过验证。
Paccept = p(d)

经过目标模型校正后，最终输出分布仍然正确，但草稿模型原本表达的不确定性被丢掉了。

开关开启 · 经典拒绝采样

从草稿分布采样，并保留完整分布

  1. 从 q 中采样 d，而不是永远选择 argmax。
  2. 把覆盖整个词表的 q 一并传入验证阶段。
  3. 从 0 到 1 均匀采样 u；当 u < min(1, p(d)q(d)) 时接受候选。
Paccept(d) = min(1, p(d)q(d))

如果草稿模型与目标模型给这个候选分配了相近概率，比值就接近 1，候选也更容易被接受。

如果 p 与 q 完全相同，每个候选都会被接受。这个开关不能主动拉近两个分布；它只是让验证器利用本来就存在的概率重叠，而不是把 q 折叠成 qδ。

一个包含 4 个 token 的例子

假设目标分布与草稿分布很接近，但并不完全相同。Token A 是两个模型共同的最高概率选择，不过其余概率质量也有实际意义，不应直接丢弃。

在窄屏上可横向滚动概率表；数值会保持在同一行。

如果开关采样到 A，条件接受率为 0.60 ÷ 0.70 = 85.7%。如果采样到 B，两个模型都给出 0.20，因此接受率为 100%。对草稿模型可能采样到的所有 token 求平均后，单步接受率为 90%。关闭开关时只能提出 A，而它仅以目标分布给出的 60% 概率通过。

采样非 argmax token 不会改变目标输出分布。 发生拒绝时，SGLang 会从与正残差 [p(x) − q(x)]+ 成比例的分布中采样替代 token。已接受的概率质量加上残差校正会重建 p；草稿模型改变的是执行成本，而不是目标采样分布。

固定版本的 SGLang 实现做了什么

阶段开关关闭开关开启
第 78 层提出候选EAGLE top-k=1 直接取 argmax按温度缩放 logits，形成 q，再采样一个 token
传入验证器的状态只有 token ID，没有完整草稿分布每个草稿步骤都传入 token ID 与覆盖整个词表的 q

第一次拒绝采样目标校正 token，并排除被拒绝的点质量候选从归一化正残差 p − q 中采样

在窄屏上可横向滚动实现对比表。

在拒绝采样路径中，请求温度会同时作用于目标 logits 与草稿 logits。随后，请求的 top-k 和 top-p 设置会过滤目标分布。若某个草稿候选不在目标分布保留的支持集内，则 p(d) = 0，它一定会被拒绝。因此，过强的目标分布截断或对齐较差的草稿模型都会削弱收益。

与版本相关的边界。 在这里固定的下游实现中，请求 top-p 会过滤 p，但不会过滤保留下来的草稿支持集 q。后续支持 top-p 的实验会显式测试两边支持集对齐；这属于实现层面的改进，并不改变上面的经典拒绝采样恒等式。

为什么最初门禁实验中的增益很小

GB300 node-136 同条件门禁 · 512 条请求

temperature=1.0、top-p=0.95、请求未设置 top-k；FP4 目标模型与 FP4 草稿模型；EAGLE 5-1-6。两个实验臂重放相同的数据切片。

开关关闭55.62% 严格草稿接受率
开关开启56.54% 严格草稿接受率
实测变化+0.91 个百分点

这个开关从 p 与 q 之间提取出了略多的重叠，但并没有让 MTP 分布本身更接近目标分布。草稿/目标权重或量化不匹配、随上下文变化的 MTP 误差，以及目标 top-p 截断，都可能让可利用的重叠仍然很小。

稳定性说明：实验组完成已统计请求后，Pod 在 DSA CUDA Graph 元数据路径中遇到 CUDA 非法内存访问并重启。仅凭时间顺序无法证明该开关导致了故障，但“运行期间不重启”的门禁条件未通过，因此完整 A/B 实验被停止。

什么时候应当期待收益，什么时候不应当

场景预期效果
随机采样解码，且 q 与 p 高度接近更高接受率可把目标模型验证成本摊薄到更多输出 token 上
贪心解码运行时走贪心验证分支；拒绝采样没有概率重叠优势
q 与 p 差异很大接受率增益很小；应优先改进草稿模型或重新对齐分布
高 batch 或验证成本很高即使接受率上升，吞吐也未必提升，因为推测计算本身并非免费
这里固定的下游实现要求使用 EAGLE/EAGLE3/NEXTN、EAGLE top-k=1、共享同一词表、默认接受阈值，并采用非确定性采样
结论。 这个开关提供的是两个分布之间更好的耦合规则，而不是更好的草稿模型。它可以在保持目标输出分布不变的前提下，把已有的草稿—目标一致性转化为更多被接受的 token。是否值得上线，仍需要稳定、固定输出量的吞吐 A/B 实验来确认。
