Start with the right mental model

Separate the model from the sampling rule. GLM-5.2 checkpoint layer 78 produces draft logits and therefore the draft distribution q. The flag does not retrain that layer, change its weights, or make its logits more accurate. It changes how SGLang draws a proposal from q, what probability information reaches target verification, and how the verifier accepts or corrects the proposal.

What speculative decoding is trying to save

Ordinary autoregressive decoding runs the expensive 78-layer target once for every new token. Speculative decoding lets the cheap one-layer MTP sidecar propose a short chain, then runs the target once over the whole chain. The target accepts the longest valid prefix and contributes one target-sampled bonus token at the boundary. More accepted drafts can therefore amortize one target verification over more output tokens.

1Draft cheaply

Layer 78 runs recurrently and proposes tokens d1 through d5.

2Verify together

The full target evaluates the proposal chain in one batched forward pass.

3Accept a prefix

Verification stops at the first rejected draft; later proposals depended on that rejected prefix.

4Correct and continue

The target supplies a correctly distributed boundary token, and drafting begins again.

Acceptance length is not strict draft acceptance. SGLang's avg_spec_accept_length includes the target's one bonus token. In a five-proposal cycle, a displayed length of 3.8 means about 2.8 accepted draft tokens plus one bonus—not 3.8 accepted drafts.

What the flag changes

Let p be the target model's sampling distribution after temperature and request filters, and q the MTP drafter's proposal distribution over the same vocabulary. The important difference is whether verification sees the full q or treats the chosen draft token as a probability-one point mass.

flag off · target-only path

Argmax becomes a point mass

  1. EAGLE top-k=1 selects the drafter's argmax token d.
  2. The verifier effectively uses qδ: probability 1 on d and 0 elsewhere.
  3. The candidate survives with probability p(d).
Paccept = p(d)

This remains distribution-correct after target correction, but it discards how uncertain the drafter was.

flag on · classic rejection sampling

Sample from and retain the proposal

  1. Sample d from q rather than always taking its argmax.
  2. Carry the vocabulary-wide q into verification.
  3. Draw u uniformly from 0 to 1 and accept when u < min(1, p(d)q(d)).
Paccept(d) = min(1, p(d)q(d))

If draft and target assign similar probability to the sampled token, the ratio is near one and acceptance is likely.

If p and q are identical, every proposal is accepted. The flag cannot make the distributions closer; it lets verification use overlap that already exists instead of collapsing q to qδ.

If the flag samples A, conditional acceptance is 0.60 ÷ 0.70 = 85.7%. If it samples B, both models assign 0.20, so acceptance is 100%. Averaging over all possible draft samples gives 90% one-step acceptance. Without the flag, only A can be proposed and it survives with the target's 60% probability.

Sampling a non-argmax token does not change the intended target law. On rejection, SGLang samples a replacement from the positive residual proportional to [p(x) − q(x)]+. Accepted mass plus residual correction reconstructs p; the drafter changes execution cost, not the target sampling distribution.

The request temperature is applied to both target and draft logits in the rejection path. The target distribution is then filtered by the request's top-k and top-p settings. A draft candidate outside the target's surviving support has p(d) = 0 and is always rejected, so aggressive target truncation or a poorly aligned drafter can reduce the benefit.

Version-specific boundary. In the pinned downstream implementation, request top-p filters p but is not applied to the retained draft support q. The later top-p-aware experiments test aligning that support explicitly; this is an implementation refinement, not a change to the classical rejection-sampling identity above.

Why it helped only a little in the original gate

The flag extracted slightly more overlap between p and q, but it did not make the MTP distribution itself more target-like. Draft/target weight or quantization mismatch, context-dependent MTP error, and target top-p truncation can all leave overlap modest.

Stability caveat: after the treatment completed its measured rows, the pod hit a CUDA illegal-memory access in the DSA CUDA-graph metadata path and restarted. Timing does not prove the flag caused the fault, but the no-restart gate failed, so the full A/B was stopped.

this pinned downstream implementationrequires EAGLE/EAGLE3/NEXTN, EAGLE top-k=1, one shared vocabulary, default acceptance thresholds, and non-deterministic sampling
Bottom line. The flag is a better coupling rule between two distributions, not a better draft model. It can turn existing draft-target agreement into more accepted tokens while preserving the target law. Its production value still requires a stable, fixed-output throughput A/B.
