GLM-5.2 H200 Top-Five Kernel MFU

A trace-ranked, counter-validated answer to two questions: which high-residency prefill family has the lowest defensible MFU, and is that value a hardware inevitability?

Verdict

Grouped MoE is both the largest residency target and the lowest defensible Tensor-Core MFU among the top five exact kernel names.

Not inevitable, but 100% is impossible for this shape. The observed 22.66% family MFU is not a physical floor. The matched gate/up counter sample reaches 23.25% useful MFU while using 68.12% of peak DRAM throughput, leaving measurable headroom. However, the 2,048-token expert shape streams about 6.61 GB from HBM and cannot exceed 34.14% useful MFU without reducing traffic or increasing weight reuse.

Instruction accounting exposes a second loss hidden by ordinary MFU: the sampled launch issues 2.126 TFLOP of Tensor-Core arithmetic for only 0.928 TFLOP of useful model work. Physical issued throughput is 53.27% of peak; useful MFU is 23.25% because grouped expert tiling amplifies work by 2.29 times.

MFU Accounting

All reported Tensor-Core families use one comparable denominator: 1,979 TFLOP/s dense-FP8-equivalent peak. BF16 MMA work is multiplied by two because H200 dense BF16 peak is half the dense FP8 peak.

MFU = useful FP8-equivalent model FLOPs / (family residency × 1,979 TFLOP/s)
Useful model work is the numerator. Padded or otherwise wasted issued Tensor-Core work is not credited.
MFUMoE = 111.325552 TFLOP / (0.248225078 s × 1,979 TFLOP/s) 22.66%
Gate/up and down cover the same 16,384 tokens across ten PP2 layers.
MFUsparse MLA = 81.776177 FP8-eq TFLOP / (0.072200344 s × 1,979 TFLOP/s) 57.23%
The 40.888089 TFLOP BF16 HGMMA numerator is doubled. The separate first dense chunk is excluded.
MFUDeepGEMM = at least 43.980465 TFLOP / (0.034211635 s × 1,979 TFLOP/s) ≥ 64.96%
All 191 same-name launches remain in the denominator; only the independently anchored q_b and o_proj work enters the numerator.

Sparse scope correction

The ranked sparse family contains exactly 70 launches: seven later chunks times ten PP2 layers. Each later 2,048-token chunk contributes 2,048 × 2,048 selected query-key pairs. NCU SASS contains BF16 HGMMA.64x64x16 and HGMMA.64x256x16. The first 2,048-token chunk instead uses ten dense FlashAttention launches totaling 2.551 ms, so its work is not assigned to the sparse exact name.

Why Useful MFU Is Only 23% in One Gate/Up Launch

NCU counts 16,220,160 executed warp-level QGMMA instructions. Nsight defines this metric per individual warp; CUTLASS defines one warpgroup as four warps issuing one collective MMA.

NQGMMA collective = 16,220,160 warp instructions / 4 warps 4,055,040
One collective QGMMA has a 64 by 128 by 32 atom.
Fissued = 4,055,040 × (2 × 64 × 128 × 32) 2.126009 TFLOP
This is physical Tensor-Core work, including padded expert rows.
Mphysical = 2,126,008,811,520 / (2 × 6,144 × 4,096) 42,240 rows
Exactly 330 M-tiles of 128 rows.
Fuseful = 2 × 18,432 × 6,144 × 4,096 0.927713 TFLOP
2,048 tokens times nine active experts yields 18,432 useful rows.
43.64% useful
56.36% padded / extra

The hardware issues 2.2917 times the useful gate/up arithmetic. This ratio is measured for one representative launch, not extrapolated as an exact average over all 80 gate/up launches.

Two different efficiencies. The sampled launch sustains 1,054.3 physical TFLOP/s, or 53.27% of dense FP8 peak. It sustains 460.1 useful TFLOP/s, or 23.25% MFU. Both are correct; they answer different questions.

Why the traffic is structural at 2K

One FP8 gate/up weight matrix has 6,144 × 4,096 bytes. Across 256 routed experts plus one shared expert, the payload is 6.468 GB before scales. NCU measures 6.460 GB of DRAM reads, 99.88% of that simple full-weight payload. This close match is direct evidence that expert-weight streaming dominates the launch.

Ignoring writes and scale metadata, useful intensity scales approximately as 2 × tokens × 9 / 257. It reaches the 411.07 FLOP/B ridge only near 5,869 tokens. The current 2,048-token chunk is therefore structurally memory-bound even with perfect instruction scheduling.

Engineering implication. The strongest directions are to increase rows per expert weight load, reduce per-expert M-tail work, overlap or pipeline weight movement more completely, or reduce the bytes fetched. Raising nominal occupancy without changing those constraints is not a sufficient objective.
What the report does not claim. The 34.14% roof holds measured traffic constant; it is not a universal kernel ceiling. The QGMMA padding ratio comes from one representative gate/up launch. Routing changes across layers and chunks, so a full-family physical-work average would require countering all 80 gate/up launches.
