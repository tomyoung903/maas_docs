08 · Measurement semantics

What these measurements do—and do not—mean

Client-visible SSE timing · natural output lengths

Single-delta caveat. 146 requests exposed only one non-empty output delta. Such a row has no observable inter-delta production interval; a zero TPOT does not mean its output was generated instantaneously.
ClockClient monotonic clock captured on receipt of each non-empty SSE output delta.
DenominatorServer-reported completion_tokens − 1; the denominator varies because source output policy is preserved.
Included timeVisible span from first non-empty output delta to last non-empty output delta.
Excluded timeClient admission wait, request transport before first output, and prompt/prefill TTFT.
Speculative decodingCompletion usage counts accepted output tokens. EAGLE may expose several accepted tokens in one SSE delta; interval acceptance gauges describe backend verification efficiency, not client chunking.
InterpretationUse this as request-level client-observed inter-output timing for the exact P/D service. It is not a kernel-only decode latency and not a direct measure of one-token GPU step time.

3. Warm-up and formal cache boundary
  1. Run a shape-matched 100-request warm-up with source output controls preserved.
  2. Wait until frontend active, inflight, request-plane inflight, and router-pending gauges all equal zero.
  3. Invoke prefill.clear_kv_blocks and backend.clear_kv_blocks; require success from both, including external HiCache clearing.
  4. Start the accepted formal replay after the second clean boundary, with no intervening request.

An oversized 1,600-row attempt was stopped early after its measured rate showed it could not finish safely. It was drained, both caches were cleared again, and none of its rows enter this formal report.
