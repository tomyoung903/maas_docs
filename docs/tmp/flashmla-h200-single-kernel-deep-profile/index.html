What the 102.464 µs contains

Three persistent warpgroups execute a double-buffered relay. The useful explanation is the dependency chain, not an invented percentage split.

1 · WG2 supplies the next tile

Read sparse indices and scales, gather two 64-record halves from the FP8 KV cache, dequantize NoPE values, handle RoPE values, fence shared memory, then signal K/V-ready.

2 · WG0 consumes and publishes scores

Wait for K/V-ready, issue QK, apply online softmax, publish the score tile, and perform the local-half PV. This lane turns WG2 arrival time into the next dependency.

3 · WG1 finishes the value path

Wait for score-ready, rescale the accumulator, perform remote-half PV, release buffers, and join the final output drain. It overlaps WG2’s work on the following tile.

Critical-path reading: sparse K/V service → K-ready barrier → WG0 QK/softmax/local PV → score-ready barrier → WG1 remote PV → final reduction/store. In steady state, WG2 is already preparing tile n+1 while WG0/WG1 consume tile n.

Why the one-record control matters

The launch shape and Tensor work remain, but every sparse selection points to one reused record. The main kernel falls from 102.464 to 79.584 µs; HBM reads fall from 145.124 to 7.838 MB; L1 global-load hit rises from 18.886% to 95.338%; eligible warps rise from 0.370 to 0.526. This is a controlled end-to-end response to locality. It does not mean the 22.880 µs difference is a serial “HBM phase.”

What PM sampling adds

A separate 1.5 µs-interval PM pass measured 104.992 µs for ordered-unique and 78.944 µs for one-record reuse, with zero merged samples. It supplies temporal activity evidence. Warp-state series came from five replay groups, so they are not aligned or summed as if sampled simultaneously.

What PC sampling adds

The separate 21-replay section capture recorded 10,376 warp-state samples: barrier was 35.55% and long scoreboard was 33.43%. This independently supports a barrier-coupled memory dependency, but the production cubin lacked CUDA line information and the shares are directional—not an internal source timeline.

Known limits
  • The historical 103.424 µs capture retained the outer main-kernel intervals, not within-kernel timestamps. The 102.464 µs Europe replay is a close reproduction, not the same launch.
  • Trace-disabled SASS is unchanged, but trace-on executes extra timestamp and record-store instructions. It validates the mechanism but cannot provide a corrected serial breakdown of production time.
  • Global-timer landmarks describe the instrumented execution. SM-cycle timestamps are only compared within one SM; they are not treated as a universal cross-SM clock.
  • The 2.881× overlap factor is summed tile-lane residency divided by its interval union for partition 45 / SM46. It is not occupancy, speedup, utilization, or a multiplier on production time.
  • PC sampling attributes sampled stalls to instruction locations. PM sampling is statistical, and warp-state replay groups are independent.
