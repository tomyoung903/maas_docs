Experiment settings

RS means rejection sampling. We test the same three configurations under two target-sampling policies. The cohorts use different source requests, so compare configurations within the same cohort.

Two request cohorts

≈60% of observed online requests

temperature 1.0 · top-p 0.95

Higher temperature and a wider top-p cutoff retain more of the target distribution.

≈40% of observed online requests

temperature 0.7 · top-p 0.7

Lower temperature and a stronger top-p cutoff produce the more restricted target distribution.

Three configurations in each cohort

1 · control · flag off

Rejection sampling off

--speculative-use-rejection-sampling is disabled. This is the comparison baseline.

2 · current SGLang · flag on

Current SGLang rejection sampling

This is the behavior SGLang supports today: the draft proposal q uses request temperature but not request top-p.

3 · our proposal · same flag

Our top-p-aware rejection sampling

The draft proposal q uses request temperature and then request top-p. Draft GitLab MR !226 ports the tested behavior to current dev; target sampling is unchanged.

Bottom line

Rejection sampling is not a fixed acceptance multiplier. Its measured benefit depends strongly on the target sampling policy; draft top-p alignment is a smaller, policy-dependent correction. In the observed online request distribution, approximately 60% use temperature 1.0 / top-p 0.95 and approximately 40% use temperature 0.7 / top-p 0.7.
