Arms ran on separate trays, outputs used their natural source controls, and CUDA graphs were disabled. Do not infer a controlled throughput delta from elapsed time.

04

Two cohorts, three modes

Within a cohort, every mode replays the same source bytes, ordinals, request bodies, ordering, and per-request seed. The two cohorts contain different source requests and must not be paired with each other.

Mode 1 · controlRS off

Original runtime. --speculative-use-rejection-sampling absent.

Mode 2 · current SGLangTemperature-aware RS

Original runtime. Rejection flag present; draft proposal q applies request temperature, not request top-p.

Mode 3 · proposalTemperature + top-p-aware RS

Audited patch present and rejection flag present. Target sampling behavior is unchanged.

Cohort policies

temperature=1.0, top_p=0.95 and temperature=0.7, top_p=0.7; neither cohort supplies request top-k.

05

Replay and row selection

1 · verifyHash before launch

Check snapshot byte size, snapshot SHA, runtime commit, patch SHA, and original source-file hashes.

2 · serveStart a clean arm

Wait for readiness, validate server metadata, then flush the prefix cache before replay.

3 · replaySubmit ordinals 1–2,000

Maximum 80 in flight, 7,200-second HTTP timeout, no in-process retry. Seed is 202608280 + ordinal − 1.

4 · checkpointCommit each row atomically

Fsync and rename each completed ordinal. On interruption, scan durable rows and submit only missing ordinals.

Natural-output and censor rule

Do not impose a 128-token cap or another replacement output limit: retain each source request's controls. For the published long-tail audit, exclude unfinished requests after every remaining request had at least 1,800 seconds to complete, and exclude completed rows with request runtime above 1,800 seconds. Never edit raw rows.

One published mask

1,907 cohort-local ordinal positions per arm

Intersect retained positions across all six arms, then require valid speculative counters in every arm. The resulting mask SHA-256 is 4720b1e65ddff2b2c79ae5fd3a60cf6e191d3d1755a2e6985d57979d1b07f0c6. This yields 11,442 displayed row instances.

Compute strict acceptance as total correct draft tokens divided by total proposed draft tokens over that mask. “Accept length” adds one target-produced bonus token per verification step; it is not accepted drafts alone.
