Direct answers

The precision, topology, TTFT source, queue behavior, cache ceiling, and disputed latency sentence all have separate answers.

Precision

NVFP4 + FP8 KV

The GB300 model checkpoint and weight path were NVFP4 (modelopt_fp4); its KV cache was FP8 E4M3. Calling the whole run simply “FP8” would be wrong.

Topology

PP4, one pod

Four GB300 GPUs hosted four pipeline stages in one standalone pod. The reference was PP8 in one pod on eight H200s.

Full-window ideal cache

82.412%

The observed 80.154% becomes 82.412% under the offline, sequential, infinite-capacity model: a 2.258-point gap, not a jump to 100%.

The “18.2% slower” sentence is numerically true but needs narrower wording. It refers to internal-TTFT P50 on the equal first 4,810 requests. Mean internal TTFT was +15.1%; P90 was +17.2%; P99 was actually 16.7% faster. Queue reduction is the dominant observed mean component, but the experiment is not causal proof that PP4 itself produced it.

Both were direct, standalone, one-token chat replays over the same filtered source. They were not identical machines with only pipeline depth changed.

Where each TTFT clock starts and stops

Client TTFT did not include prefill from a prior phase, and it did not start when the source row was read. It began only after the HTTP request headers were sent.

How the queue was driven

The test used a bounded-backlog, closed-loop client. It held at most 80 admitted requests in flight; it did not hold the SGLang queue at a fixed length and did not tune load to a TTFT target.

Why client TTFT remained finite. The closed loop cannot create more than 80 admitted requests. It keeps the worker saturated, but completions continuously recycle slots. The resulting TTFT is a saturated-capacity latency, not production-cadence latency and not an SLO-controlled latency.

Do not call the entire ideal-minus-observed gap “eviction.” The ideal model commits each request before the next lookup. The real replay had up to 80 concurrent requests, so later requests can arrive before earlier shared KV is committed. Defensible rewrite. “On the equal first-4,810-request prefix, GB300 client TTFT fell mainly alongside a 7.526-second reduction in mean queue time; mean internal prefill was 0.306 seconds slower and the residual was 0.278 seconds larger. This is a descriptive decomposition of two differently configured saturated systems, not a causal PP-only attribution.”

The queue decrease is larger than the net 6.942-second client improvement because slower internal work and a larger remainder offset part of it. This supports “queue was the dominant observed component.” It does not prove why the queue changed: service capacity, maximum-running limit, chunking, GPU generation, precision, pipeline depth, and cache outcomes all differ.
