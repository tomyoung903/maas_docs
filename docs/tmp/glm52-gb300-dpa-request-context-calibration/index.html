01 · The experiment program at a glance

Three stages answer different questions. Only the historical observation has numbers; the new calibration and causal control have not produced data.

Stage A · historical input

Siqin-style one-hot fit

A prior DP16 calibration increased active logical KV and request count on one loaded rank, then fitted whole-step time. It produced the router penalty later summarized as a large linear request term plus a small negative quadratic term.

Observed · raw 26-cell set not preserved

Recreate the one-hot surface with controlled request count and cached length, but report DSA, sparse MLA, MoE, collectives, and whole-step envelopes separately.

Stage C · author recommendation

Fixed-logical-load placement control

A future extension would keep the same 64 logical requests while redistributing them among eight ranks. It would test—not assume—whether observed decode rows, padding mode, and shared MoE/collective work remain comparable as the hot rank’s local attention load changes.

Tom’s methodological warning is right; the exact “2×” is not measured

When only one DPA rank receives requests, increasing its request count also increases the shared, synchronized MoE workload. Regressing whole-step time against that rank’s request count therefore mixes a local-attention slope with a group-shared MoE slope. If MoE is about half of decode time, a roughly twofold overstatement is plausible—but batching, graph buckets, collectives, overlap, and nonlinear kernel scaling mean the multiplier must be measured rather than assumed.

04 · How the two axes isolate the costs

The matrix supports two complementary slices. Neither slice alone is sufficient; together with critical-path attribution they support estimating an attention proxy, subject to physical-work checks and rank-local residual validation.

Hold N fixed; increase L

The number of active sequences stays constant while each sequence exposes more cached history. The DSA indexer scans the longer history; above the sparse threshold, sparse MLA should remain near its selected-position budget and be much less context-sensitive. Both must be measured separately. Logical MoE token count should remain approximately fixed, while physical EAGLE rows and padding still need verification.

8K each→ 32K each→ 80K each

Hold logical context fixed; increase N

Equal-logical-context pairs keep nominal DSA history input constant while changing sequence count. They do not equalize sparse-MLA work or physical allocation. The difference also includes per-sequence launch geometry, query-side work, scheduler/graph effects, and—unless controlled—shared model work.

Trank-local proxy ≈ interval union of DSA and sparse MLA audit residual rank-sensitive work from projections, norms, KV writes, EAGLE/MTP, graph padding, and scheduling
Why total step time is not the desired coefficient:

MoE is synchronized across the TP/EP participants. Loading one DPA rank can increase shared MoE work and can also change EAGLE row geometry or padding. Regressing whole-step time directly against that rank’s request count assigns those group effects to its routing penalty. Phase attribution must therefore use critical-path intervals or mutually exclusive wall-clock envelopes, not subtraction of overlapping raw kernel time.

Decisive pattern:

If observed physical row geometry and the shared MoE/collective envelope remain comparable while the target-rank attention proxy changes with the hottest local batch—and other rank-local residuals remain small or explicitly modeled—the request-distribution effect is identified without borrowing the one-hot run’s shared-work slope. After that, a natural-traffic A/B can compare total_tokens, total_requests, and a request-first policy with a projected-KV safety guard.

07 · Operational execution plan

The preserved runner is the starting point, not the final protocol. The expanded run separates high-sample timing from short profiler captures, observes physical EAGLE and MoE work in the logical-load control, and makes every completed observation independently resumable.

Freeze contract

Write image, model, SGLang commit, launch arguments, nodes, seeds, cell inventory, and output path before reserving GPUs.

Pass ready gate

Require all eight ranks, exact server configuration, EAGLE, routed-rank control, metrics, and a one-cell decode smoke test.

Prime placements

Warm deterministic 80K lane–rank pairs, then prove every measured request reports the expected cached prefix.

Run timing blocks

Collect three seeded repetitions of both 24-cell surfaces with 384 fixed output tokens per request.

Trace and close

Capture 96-token cells in six-cell shards on both nodes; export, checksum, classify, fit, and release.

Durable progress and restart semantics

The recent multi-node run showed that “the pod is Running” is not a sufficient durability boundary. This experiment adopts the same principle at cell granularity.

1

Atomic observation

Each mode–cell–repeat ID writes a temporary result, fsyncs it, atomically renames it, and updates the completed-ID ledger. A resumed runner submits only IDs that do not validate.

2

Bounded trace shard

After at most six cells, stop capture, export report and SQLite, write checksums and cell boundaries, then start the next shard. Never make the whole program one profiler transaction.

3

Explicit recovery

A replacement server passes the immutable contract, flushes and re-primes deterministic placements, reruns one smoke cell, then continues missing IDs. Cache residency is never durable state.

Slow startup is not failure:

If a cold image pull has no warning events and keeps progressing, preserve it. The recent GB300 run had one healthy node spend roughly 11 minutes pulling before model load and autotuning; deleting it early would only restart the same cost.

2026-09-01 · current verification
Zero Kubernetes resources and zero measurement artifacts remain

Only the reusable local manifests and scripts remain. Possible empty startup residue on the former node-local host path was not re-audited and is not treated as evidence.

Analysis checks required after a rerun
  • EAGLE work matching: group cycles by target verification width or accepted-token count. Different speculative outcomes can change per-cycle work even at the same N and L.
  • Physical-work contract: record logical requests separately from global_dp_buffer_len, dp_padding_mode, graph bucket, verification rows, expert load, and collective shape. Fixed logical input is not proof of fixed shared work.
  • Steady-state selection: exclude graph capture, first-step setup, final partial batches, and cache-warm operations from the fitted window.
  • Rank-local residual: after the DSA+sparse-MLA interval union, audit projections, norms, KV writes, EAGLE/MTP, scheduler, and graph-padding time before using the proxy as a routing coefficient.
  • Production validation: replay natural mixed-rank traffic after the one-hot microbenchmark. The calibration is useful only if it improves prediction of the rank-sensitive critical path online.
Downstream experiments that are still proposals
  • Author-recommended matched-placement control: run the fixed-64-logical-request layouts above and rotate the hot rank while matching observed physical work. It was not selected in optim_exp6, and no cells have been collected.
  • Router A/B: replay the same natural trace with total_tokens and total_requests while KV headroom is demonstrably safe. Existing rank-count heatmaps do not prove a TPOT effect.
  • Hybrid router: admit only ranks with safe projected KV headroom, then minimize projected active requests and use KV pressure as a tie-breaker. This requires implementation; the current startup flag selects one static method.
