Definitions and Governing Relationships

The table uses recomputed token ratios and the same trace-anchored, precision-normalized MFU convention for every experiment.

Pi=total prompt tokens in experiment i
Ci=server-reported cached prompt tokens in experiment i
Ni=Pi − Ci
hi=Ci / Pi
Ppeak=4 × 13,500 TFLOP/s = 54 PFLOP/s
MFUi=Fi,FP4-eq / (Δti × Ppeak)
Fi,FP4-eq is classified Tensor-Core model math allocated to the scheduler-selected stable interval. NVFP4 work is weighted ×1, FP8 ×3, and verified BF16 ×6 against dense B300 FP4 peak; unverified work is excluded rather than assigned an invented precision.

Plainly: cache hit is cached prompt tokens divided by all prompt tokens. Stable MFU is executed, precision-normalized model math divided by elapsed stable time and the four-GPU dense FP4 peak.

Queue-Free Service TTFT (Internal Queue Excluded)

These one-token measurements answer a deliberately narrower question: once a request reaches its first PP0 GPU work, how long until the token is ready or placed on the server response path? The table uses each report's existing stable completion cohort and removes both pre-server waiting and SGLang's internal scheduler queue.

tGPUstart,i=first device-0 PP0 alloc_extend_kernel for request i's first chunk
TGPUready,i=tready,i − tGPUstart,i
TGPUwire,i=tsend,i − tGPUstart,i
Wexcluded,i=pre-server/API-dispatch wait + SGLang queue wait + CPU dequeue-to-GPU marker gap
The CPU scheduler's exact forward_entry_time was not logged. Therefore the first-GPU marker is an exact trace event but a slightly late proxy for dequeue, making these GPU-service durations slight lower bounds on CPU-dequeue service TTFT.

Plainly: the hundreds of seconds previously seen under burst pressure belonged mostly to queue drainage. They are intentionally absent here. The percentile gates below are the document's numerical reference thresholds; after removing queue time, this is not conventional client-observed TTFT or a contractual end-to-end SLO verdict.
