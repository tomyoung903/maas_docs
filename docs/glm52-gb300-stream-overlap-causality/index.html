GLM-5.2 · GB300 · TP8 decode · controlled scheduling experiment

Why the four CUDA-stream overlaps help

The heavy Q/K and MoE pairs do execute concurrently on different SMs because their blocks cannot fit together on one SM. The two small DSA pairs may co-reside on one SM. The real performance mechanism is broader: independent grids expose enough ready blocks to fill otherwise unused GPU capacity, and the recovered overlap exceeds the contention cost.

Verdict

Yes for the heavy pairs, but “different streams use different SMs” is not the general rule. CUDA schedules thread blocks, not whole streams, onto available SMs. In this trace, resource limits force concurrently active heavy Q/K and MoE blocks onto different SMs. Small DSA blocks can share an SM. Removing all four source-level forks made the graph slower.

What can be proved about SM use

GB110 exposes 152 SMs, 233,472 B shared memory per SM, and 65,536 registers per SM in the captured target record. A resource sum above either limit is a hard same-SM exclusion for one block from each kernel.

Q/K projection · different SMs required

Q projection block224,044 B
K projection block223,020 B
SQ + SK = 224,044 B + 223,020 B = 447,064 B > SSM = 233,472 B

MoE routed GEMM · different SMs required

Routed block register floor65,536

A 512-thread block at 128 registers per thread consumes the entire per-SM register file before any shared-expert block is added.

Rrouted = 512 × 128 = 65,536 = RSM

Small DSA pairs · same SM is possible

Rotate pair shared memory1,024 B total
Quant/store register floor6,528 total

Their blocks can co-reside if warp, block, and other allocation limits also permit it. Separate SMs are not required.

Important: a CUDA stream does not own an SM set. Streams provide independent dependency queues. The GPU work distributor places eligible blocks on any SM with sufficient registers, shared memory, warp slots, and block slots.

The actual reason it helps

Native concurrency is not free: overlapping heavy kernels slow one another. The steady-step paired means expose the full tradeoff and preserve an exact per-observation accounting identity.

The recovered concurrency remains larger than the slowdown.

2.300 ms recovered overlap − 1.098 ms contention = 1.203 ms less GPU-active time; adding 0.134 ms fewer inactive gaps gives 1.336 ms mean wall-time benefit.

So “uses multiple SMs” is only part of the answer. Heavy pairs must occupy different SMs while concurrent; small pairs may share an SM. In both cases, the useful mechanism is exposing independent blocks so the scheduler can consume capacity that one branch cannot use at that instant. The A/B proves that this scheduling opportunity is net-positive for this graph shape.

Proof boundary

  • CUPTI kernel intervals are grid-lifetime timestamps, not a per-CTA log of physical SM IDs. The report does not claim an exact SM-number assignment.
  • For resource-excluded overlapping pairs, same-SM co-residency is impossible; therefore simultaneously resident blocks from those pairs must use different SMs.
  • For the small pairs, resource arithmetic proves only that same-SM co-residency is possible, not that it happened in every cycle.
  • The serialized control adds graph dependency nodes. Its latency delta is the net cost of removing these concurrency opportunities, including changed contention and dependency gaps.
  • The conclusion is scoped to GLM-5.2 FP8, TP8, B=100 decode on this GB300 image and graph. It is not a universal promise for every batch shape.
