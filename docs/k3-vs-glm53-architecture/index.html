Kimi K3 vs GLM-5.3

Two MoE models with different ways of carrying history, running experts, and reusing intermediate representations. Those differences matter directly to cache capacity and serving bottlenecks.

Reviewed · 10 September 2026K3 source · cc1ecdadaf37GLM source · 6d08e28b0c06Architecture ≠ measured throughput
The compact answer

K3 combines recurrent memory, narrower routed experts, and learned reuse across depth.

Our GLM-5.3 checkpoint uses MLA with sparse position selection and conventional residual connections. K3 instead mixes Kimi Delta Attention with MLA, surrounds its routed experts with a latent bottleneck, and adds Attention Residuals.

Keep three different ideas separate: KDA summarizes sequence history; MLA compresses each token’s KV representation; latent MoE compresses features passed through the expert network.

02 · How history is represented

KDA summarizes history; DSA selects historical positions

K3 interleaves recurrent and token-attention layers. Its one-based layer pattern is:

Kimi Delta Attention

Each new token updates a recurrent state representing earlier history, using learned forgetting and update gates, then reads from that state.

There is no separate historical K/V entry for every token in a KDA layer. Its live recurrent-state size is fixed for a given model and sequence.

Short causal convolutions participate in Q/K/V processing. Prefill uses chunked kernels: recurrent semantics do not require token-at-a-time Prefill execution.

K3’s MLA layers

These retain tokenwise compressed KV and perform causal attention over historical positions, complementing the recurrent summaries with direct access to history.

The K3 MLA implementation also applies a learned output gate and skips RoPE in this text-attention path.

Because these layers remain, the complete K3 model does not have constant memory or context-independent attention cost.

GLM: keep compressed KV, then select what to read

GLM uses MLA to retain compressed tokenwise KV throughout its layers. DeepSeek Sparse Attention (DSA) adds a lightweight indexer that selects up to 2,048 historical positions for the expensive attention operation. The indexer still searches historical positions.

Some layers reuse the previous layer’s selected indices. They still have their own layer-specific KV: reusing the selected positions does not mean reusing another layer’s complete attention cache.

03 · Where routed experts operate

Latent MoE narrows the routed feature space

K3’s router reads the original full-width hidden state. A common projection then compresses the expert input; selected experts operate in that narrower space. Their outputs are combined, normalized, and expanded back to the model’s hidden width.

ht: full-width hidden vector for token t. zt: routed-expert latent vector. ℝd: real vector space of dimension d.

GLM’s routed experts instead operate directly on its full hidden width. Both models still have top-k routing and an always-active shared branch.

Narrower experts do not imply a blanket reduction in model compute. K3 activates more experts, has more layers, and adds common projections and normalization. Architecture alone does not establish a higher serving TPM.

Source: KimiK3MoE, especially the router, shared branch, latent projections, and forward path.

04 · Reusing representations across depth

Attention Residuals are not token-to-token attention

GLM ordinarily carries a residual stream forward through additions. K3 additionally lets each token mix representations saved at earlier block boundaries.

Earlier block snapshots
+ current residual state
→
Learned scores
Softmax over depth
→
Weighted mixture
for attention or MoE
  1. For one token, collect the available earlier block representations and the current residual state.
  2. Normalize each candidate for scoring and assign a learned scalar score.
  3. Apply softmax across those depth candidates.
  4. Mix the original, unnormalized candidate vectors using those weights.

The question being answered is: “Which earlier depth’s representation should this layer reuse?” It is not “Which previous sequence token should I attend to?”

The representation bank belongs to the current forward pass; it is not persistent sequence KV. Residual additions still exist inside blocks—K3 does not replace every addition with attention.

Source: aggregate_stream_torch and the Attention Residual bank.

05 · Two additional distinctions

Activation and multimodal processing also differ

SiTU versus SwiGLU

K3’s SiTU gated activation softly bounds the gate branch with tanh; the checkpoint also enables a soft bound on the other multiplicative branch. This differs from the ordinary SiLU-based gated FFN used by the audited GLM checkpoint.

SituAndMul implementation.

Vision encoder + language backbone

K3’s wrapper combines a MoonViT3d vision tower, a multimodal projector, and the language model. Image/video inputs therefore add a processing path absent from our text-only GLM deployment.

That is not evidence that a text-only K3 request always pays image-encoding cost.

06 · Implications for our serving experiments

K3 has two different cache-capacity constraints

MLA KV pool

Stores tokenwise attention history. Its occupied capacity grows with cached context length.

Only K3’s MLA layers use this kind of growing attention memory.

KDA recurrent-state pool

Stores live sequence states and additional retained copies required by caching or speculative execution.

Capacity depends on concurrent sequences and state-copy policy, not just total KV-token slots.

  • A concurrency limit can come from state storage. K3 can run out of KDA-state slots while its MLA KV pool still has space.
  • Prefix reuse must preserve the right state. An arbitrary cached KV page is not by itself a substitute for the recurrent state at the matching prefix boundary.
  • P/D transfer must cover both representations. For K3, transferring the growing MLA KV alone is not sufficient to resume all layers on Decode.
  • Long-context cost changes, but does not disappear. Most K3 layers avoid repeated token-history scans, while the remaining MLA layers still attend over growing history.
  • Compare useful service throughput, not model names. Input contexts, output lengths, quantization, kernels, routing, concurrency, and cache policy must be controlled before attributing a TPM difference to architecture.

Bottom line: K3 reduces dependence on historical-token scans in most layers, while adding a larger expert network and more sophisticated residual processing. Its bottlenecks need not resemble GLM-5.3’s; this explanation is not a measured performance ranking.

Source: the two-pool configuration and serving notes in the pinned K3 serving guide.
