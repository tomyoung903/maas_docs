跨 DP 动态调度框架 (DyCP)（特性 Owner）

蚂蚁集团-超级计算部-程序语言与编译器-大模型推理加速 · 2025.06 – 2026.07

  1. 问题与规模效应：MoE 的 dispatch & combine 构成强同步，attn 耗时由最慢的 DP rank 决定；线上观察该不均衡随 DP 度数系统性恶化（长度重尾，而 barrier 取 N 个 rank 的 max）(DyCP RFC)。
    公开核验：RFC vllm#29295 · 本人提交 · 2026-10-29 关闭
  2. 框架与首个应用：引入 Domain 作为中心化调度的作用域（不跨机，EP128 下并行开多个 Domain），域内统一调度算力与各 DP 的剩余 KV 容量，支持同一 step 内并存跨 DP 的 CP 请求与普通 DP 请求，并按 Batch × CP reqs 二维抓图以对齐 CP 集合通信；首个应用为请求粒度动态 CP，把长请求 attn 切到有 slack 的 rank、将 attn 耗时从 max 拉向域内均值。4×H800×8 上 DeepSeek R1 取得 20%∼100% 收益，Kimi K2.5 已在蚂蚁灰度上线并拿到 8% 的 TPOT 收益 (vLLM DyCP(待合入), vLLM-Ascend DyCP(待合入))。

DeepSeek Sparse Attn 分片上下文并行 (Sharded CP)

蚂蚁集团-超级计算部-程序语言与编译器-大模型推理加速 · 2025.06 – 2026.07

  1. 问题定位：DSA 的 Lightning Indexer 仅含单次矩阵乘 + top-k，且结果是一个向量，需完整激活做全局选择而无法 TP 切分；TP 组内每卡重复执行完整 Indexer，计算量随 seq len 线性增长，冗余随 TP 规模线性增长 (DSA-CP RFC)。
    公开核验：RFC vllm#30055 · 他人提交 · 2026-10-29 关闭
  2. 方案与实现：在 vLLM 实现 Prefill 的 TP→CP→TP 状态转换，attn 与 MoE 阶段转换为 CP，使 Indexer 计算量与稀疏 gather 访存量降至 1/CP。8k 上下文下，DeepSeek V3.2 在昇腾 910C 上 Prefill 吞吐提升 336%、在 H200 上提升 30%；DeepSeek V4 在 H200 上吞吐提升 15%。
    公开核验：RFC 引用的昇腾实现 vllm-ascend#4702 · 他人提交 · 2025-12-06 合并 · commit 与 co-author 中未见本人。未找到本人署名的公开实现；吞吐数字未核实

细粒度张量并行优化

蚂蚁集团-超级计算部-程序语言与编译器-大模型推理加速 · 2025.06 – 2026.07

  1. 优化思路：Decode 阶段为 memory-bound，纯 DP 下每卡需存放并读取完整权重，显存与访存双重受限；而现代 MoE 模型占权重大头的 Expert 并不受 attn 并行方式约束，DP 域之间存在冗余的权重存储。据此对 o_proj、lm_head、embedding、dense FFN 四个大权重模块启用跨 DP 组的细粒度 TP，用少量通信换取显存与访存收益。
  2. 差异化切分方案：按各模块计算特性定制通信模式——o_proj 行切 (All-to-All → GEMM → Reduce-Scatter)，lm_head 列切 (All-Gather → GEMM → All-to-All)，embedding 列切查表 (All-Gather → lookup → Reduce-Scatter)，dense FFN 列切升维 + 行切降维、仅首尾通信 (Embedding PR, Dense FFN PR)。
    公开核验：vllm-ascend#2616 · 他人提交 · 2025-12-12 合并 · 本人为 co-author；vllm-ascend#4999 · 他人提交 · 2025-12-18 合并 · 本人为 co-author
  3. 收益与取舍：TP=8 下四模块合计单卡节省显存 9.7 GB、TPOT 净优化约 2 ms；其中 o_proj 单层权重仅 117 MB，切分引入的通信开销反使 TPOT 劣化 1.5 ms，故 TPOT 敏感场景仅开启其余三个模块，可换取 3.9 GB 显存与 3.2 ms TPOT 收益。目前正推动该方案向 vLLM 主社区适配（RFC 撰写中）。

系统性能优化与方案设计

蚂蚁集团-超级计算部-程序语言与编译器-大模型推理加速 · 2025.06 – 2026.07

  1. Prefix Cache CPU Offloading：参与设计 CPU Prefix Cache 方案，通过 HBM 与 DRAM 双写、按层异步读取，将 10% CPU Cache 命中率转化为 7.6% 的 QPS 提升。
  2. 性能与精度排查：通过 profiling 定位 NPU 算子缺陷，累计推动 CANN 侧修复 N 个算子精度问题（如 MLA 在特定输入长度下的精度错误），保障线上服务稳定。
  3. 三级 Prefix Offload 方案：KV Cache 做 layer shard 之后与内存分页管理冲突，长请求的 KV Cache 读取需要跨页；在方案讨论中提出 CPU 融合算子方案并完成草稿实现，该方案最终被采纳，读取提速约 10×。
  4. MoE 卸载实现：重构 vLLM-Ascend 的 MoE offload，实现 NZ 格式权重的 MoE offload，在性能几乎无损的前提下，单卡节省显存 1.3 GB（GLM 5.1）(NZ weight offload PR)。
    公开核验：vllm-ascend#11945 · 他人提交 · 2026-07-20 合并 · 本人为 co-author
  5. 扩展模型上下文窗口：为 Qwen3 Decode 节点实现 Torchair 模式的 YaRN 扩展，将有效上下文长度从 40k 提升至 128k。
  6. 参与 Qwen3-235B、QwenCoder-480B、DeepSeek R1/V3.2/V4、Kimi K2/K2.5/K2.6、GLM 4.7∼5.2 等模型的性能调优，推动上线。

训练框架特性开发（TorchTurbo Main Contributor，已开源）

蚂蚁集团-超级计算部-后训练服务部-大模型后训练优化 · 2026.07 – 至今

  1. 完成 DeepSeek V4 后训练适配：针对稀疏注意力与压缩 KV 的跨序列依赖，基于 Ulysses SP 实现跨卡 KV 聚合及全局位置/索引计算，打通 SP、EP 与 FSDP2 混合并行，已在昇腾 4,000 卡集群落地。
  2. 优化 MoE 路由负载均衡：实现并调优 AUX loss 与 router Z loss，前者直接约束专家负载分布，后者惩罚 router logits 的 logsumexp、缓解 bf16 下 logit 饱和造成的路由塌缩，分别将专家负载变异系数（CV）降低 22.7% 与 31.6%。
  3. 优化 CPU offload 策略：为提升蚂蚁内部训练框架在多机 + CPU offload 场景下的训练速度，将 optimizer 参数卸载至 DRAM，权重与梯度仍保留在 HBM 上。Qwen 3.5 35B / 122B 相比不开 offload 分别节省显存 4.2 GB / 5.8 GB，同时相比全量 offload 训练性能分别提升 15% 与 59%。
  4. 实现 chunk loss：针对训练中完整 LM head 与 CE 产生的显存尖峰问题，训练时不再执行完整 LM head，而是返回 hidden state、以 chunk 为维度计算，Qwen 3.5 35B 32k SP4 场景下单卡节省显存约 4 GB。
  5. 支持 AC（Activation Checkpointing）显存优化，Qwen 3.5 35B 单卡显存峰值降低 3.7 GB。
  6. 实现 VLM 视觉编码器负载均衡：SP 组内各卡重复编码本 DP 分片的图像，且分片间 patch 数差异使视觉阶段负载倾斜；将各 SP 组代表 rank 发布的图像汇聚为全局媒体池，按 patch 数 LPT 打包均衡分配至全部 rank 编码，再经可微 all-to-all 分发回所属组，反向梯度沿同一通信图回传、无需缩放修正；均衡能力可复用并接入引擎与 FSDP2 并行规划 (Vision LB PR)。
    公开核验：TorchTurbo#1 · 本人提交 · 2026-10-16 合并
  7. 实现 LoRA DPO：以冻结的共享基座充当 reference，省去独立 reference 模型的显存驻留；reference 前向以 eval 模式执行，避免被计入训练 micro-batch 造成 MFU 统计失真，并兼容 SP 尾部 batch 与断点恢复 (LoRA DPO PR)。
    公开核验：TorchTurbo#64 · 本人提交 · 2026-11-17 合并
  8. 实现本地模型 forward 的 logits_to_keep：hidden states 在投影到词表前按需选取，DPO 不再对整条序列（含 prompt）做 vocab 投影，削减 logits 的显存与计算开销；覆盖 Bailing Hybrid、GLM-MoE-DSA、Kimi K2.5、LLaDA2 及 MTP、生成、拒采样场景 (logits_to_keep PR)。
    公开核验：TorchTurbo#70 · 本人提交 · 2026-11-16 合并
  9. 支持 Qwen3.8 后训练：新增对话模板，规范化偏好轨迹中的 OpenAI 工具调用，保留历史 thinking 并以工具调用作为 loss 边界 (Qwen3.8 模板 PR)。
