Two endpoint views.

In the TP = 8 FlashInfer oneshot_lamport path captured in the B = 100 trace, each GPU holds a different partial tensor Si. Every other rank needs that tensor. The kernel explicitly writes seven remote rank buffers, so NVSwitch routes seven point-to-point copies. It does not use the separate NVLS multicast mechanism.

The correction

The familiar eight GPUs connected to one fabric sketch is a topology abstraction—not proof of the algorithm’s traffic pattern. For this traced kernel, the source loop proves seven per-rank stores; a better picture follows those packets across each GPU boundary.

Do not cross the conventions.

Never divide TX + RX bytes by a one-direction 450 GB/s peak, and never divide TX-only bytes by the 900 GB/s aggregate peak. Either mismatch creates a factor-of-two error.

Interpretation boundary

What this page proves—and what it estimates

Proved by algorithm geometry

Seven remote copies per source, 56 directed node-wide transfers, and the equivalence of matched directional versus aggregate accounting.

Payload-equivalent, not counter-measured

The 66.31 and 132.62 GB/s readings use payload size divided by the 129.7205 µs average traced kernel duration. That duration also contains polling, reduction, fused normalization, and local HBM work.

Topology is schematic

The central fabric represents NVSwitch routing. It deliberately does not claim literal switch-chip placement or cable geometry.

Algorithm identity is part of the traffic model.

The seven-copy conclusion applies to the captured FlashInfer oneshot_lamport implementation and ordinary peer-memory LSA paths. Do not reuse its numerator for an NVLS/multimem kernel without reading that kernel and, ideally, collecting NVLink counters.
