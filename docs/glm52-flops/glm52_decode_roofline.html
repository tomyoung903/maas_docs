GLM-5.2 100K Decode Roofline

The five familiar PFLOP figures are a 100,000-token prefill ledger. This page converts them into the one-query decode work and minimum data demand needed to decide whether each operation is HBM-bandwidth-side or compute-side.

Answer

One-query decode verdict: MLA projection GEMMs, dense MLP GEMMs, MoE/router GEMMs, and indexer candidate scoring lie decisively on the memory side of the ideal H200 roofline. The fused sparse MLA score/value scan is borderline: its 192–212 FLOP/byte intensity straddles the ≈206 FLOP/byte BF16 ridge, so the defensible classification is mixed, not automatically HBM-bound.

Do Not Mix the Two Ledgers

The prefill column is cumulative logical work over a fresh 100K-token prompt. The decode column is one new target query against an already populated 100K-token context. Neither column is per-GPU measured throughput.

If an operation's arithmetic intensity is well below the relevant ridge point, moving its compulsory bytes takes longer than ideal arithmetic and it lies on the bandwidth side. Near the ridge, classify it as mixed unless hardware counters settle the question.

These H200 peaks are a reference roofline, not a claim that the kernels attain peak bandwidth or peak Tensor Core throughput. The three GEMM groups use FP8-heavy paths; the MLA scan is compared with the BF16 ridge because its fused attention arithmetic and cache representation include BF16 work/data.

The ideal HBM floor is data demand divided by 4.8 TB/s. It is a lower bound, not a latency prediction. Small matrix rows, random gathers, page tables, launch latency, DeepEP communication, expert imbalance, and collectives can make elapsed time longer without changing the algorithmic roofline position.

The fused value accumulation reuses the 512-byte latent already fetched for scoring; it does not require a second compulsory KV read. This places the scan almost on the BF16 ridge.

The indexer continues to grow linearly with context length because it scores every cached candidate in 21 refresh layers. Sparse MLA stops growing after TopK reaches 2,048 because each of the 78 attention layers scans only the selected records.

Measurement needed for a hardware verdict: capture representative kernels with Nsight Compute counters for DRAM bytes read/written, DRAM percentage of peak, L2 hit rate, and Tensor Core utilization. “Bandwidth-side” does not mean “saturates 4.8 TB/s,” and a bandwidth-side kernel need not dominate total TPOT.
