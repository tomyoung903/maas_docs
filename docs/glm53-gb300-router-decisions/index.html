GLM-5.3 · Taiguo GB300 · live production routing

One request, two placement decisions

The frontend first chooses one of five Prefill PP4 workers. It then runs a separate contest over sixteen Decode DP-rank candidates. Both scores use 64-token block-equivalent units, but they deliberately optimize different work.

The compact answer

Prefill subtracts reusable cache from projected work; Decode ignores that cache score and balances each rank's live batch.

Smaller score wins. With router temperature zero, there is no probabilistic softmax choice. Exact equal-score ties are randomized uniformly. A request is not permanently assigned to one “pod” at ingress: Prefill placement and Decode placement happen in sequence and may point to different machines.

There are more than three signals. “Backlog, local cache, shared cache” is the useful headline. In the implementation, local cache is split into device, host-pinned, and disk/external tiers; the uncached tail also receives a context-depth surcharge, and existing backlog is converted from tokens into modeled time.
Figure 1 · when each choice is made

Decode is selected before Prefill GPU work finishes

The two router calls are close together in control-plane time, while Prefill compute and KV transfer continue asynchronously afterward. This early Decode choice gives the receiver time to establish the P→D transfer path.

Everything is converted to block-equivalent cost

The unit is one 64-token KV block. Existing work and the incoming prompt add cost; reusable cache subtracts credit. The score is a ranking objective—not a promise that one block always equals the same wall-clock latency.

Why the router replaces raw backlog with modeled time

The same remaining token count is not equally expensive at every context position. The deployed curve model estimates how long the current queue has left, then expresses that duration as an equivalent amount of position-zero work using 30,762 tokens/s. The correction removes the raw Q/64 already present in the base term and inserts the time-equivalent value once.

Case B · shared locality is not enough

A carries +1.2 backlog blocks but has only +2 shared blocks

+1.2−2 × 0.5=+0.2

A remains 0.2 blocks more expensive, so B wins before depth/time differences.

No double credit.

If a block is both in candidate A's device prefix and in the global shared cache, A receives the 1.0 device credit—not 1.0 + 0.5. A candidate without that local prefix can receive 0.5 shared credit for the same position. This is why global shared cache can narrow a locality disadvantage without erasing the preference for device-local KV.

What did contribute

Across 227,044 Prefill candidate evaluations, the mean device-local credit was 243.79 blocks and the mean lower-tier per-worker credit was 5.41 blocks. The latter combines weighted host/disk/shared terms; the independently observed shared contribution was zero, so the nonzero portion came from local lower tiers.

!

Operational reading: in this snapshot, actual placement was driven by backlog, context depth, device locality, and a small local lower-tier signal. The 0.5 shared weight was wired but inert.

Selection is not only an argmin

Eligibility, queueing, and overload can change the candidate set

A

Prefill admission filter

A Prefill worker can be removed when active Prefill tokens exceed 3,000,000. Each Prefill worker has DP size 1, so this applies directly to its only rank.

B

Global Prefill queue

An empty queue starts parking arrivals when every eligible Prefill worker is above 256 × 8,192 = 2,097,152 active tokens. Once backlog exists, later arrivals also queue until it drains. The deployed policy is WSPT; final selection occurs on admission.

C

Eight-second affinity escape

If the cache-score winner has more than 8,000 ms of modeled Prefill work left, the router replaces it with the eligible worker predicted to free soonest. Cache affinity is therefore a preference, not an obligation.

D

Decode capacity filter

The threshold is 93% of 48,994 KV blocks per rank. A decoder group is filtered only when all of its known ranks are overloaded; otherwise all ranks stay candidates and their individual scores steer traffic away from hot ranks.

E

Prediction and replica synchronization

Three frontend replicas synchronize router state. Each still decides from its latest local snapshot. The 12-second predict-on-route index fills the delay before KV events arrive; it does not make the selection a centralized transaction.

The exact answer to “when is routing decided?”

  1. Prefill worker: after preprocessing/tokenization and any admission wait, after local and shared cache metadata queries complete, immediately before the Prefill RPC is dispatched.
  2. Decode group and global DP rank: immediately after Prefill routing has created the bootstrap metadata and dispatched the Prefill stream; it does not wait for Prefill GPU completion or KV transfer completion.
  3. Execution begins later: the selected Decode rank prepares the receive side, waits for the request's transferred KV, and then owns subsequent Decode attention/cache state.
