GPU弹性资源调度（快照恢复与重启）

阿里控股-智能引擎 · AI infra-大模型推理优化实习生 · 2026.06 - 至今 · 推理引擎（十万卡集群）

  1. 针对推理服务分时复用 GPU 场景下冷启动代价高的问题，设计并实现基于 NVIDIA cuCheckpointProcess Driver 570+ API 的 GPU 全进程状态冻结/恢复机制：冻结时 Lock 阻塞新 CUDA API 调用并等待 in flight GPU 操作完成，之后Chekpoint 将 GPU 全部状态（模型权重、KV Cache、CUDA Graph、JIT 编译 kernel、CUDA context 与 CUDA stream）整体迁移至 Host RAM 并释放 GPU 占用；恢复时通过 Restor 将 Host RAM 中的 GPU 状态写回 HBM，再通过Unlock 恢复 CUDA API 调用能力，冷启动时间从15~20min 降低至3~5min
  2. 针对 GPU 管控平台需求，为 SGLang 推理引擎新增 /suspend、/resume、/is_suspended API；为平台提供分级内存释放能力 L1（KV Cache + CUDA Graph）L2（+ 权重 + 全状态 checkpoint），经 /suspend /resume HTTP 端点暴露给外部编排器，skip_checkpoint 参数支持编排器托管。
  3. 针对 NCCL checkpoint 后难以恢复的问题，设计 NCCL 分层销毁方案 checkpoint 后 NCCL communicator 失效 → 只销毁 GPU 端 NCCL group、保留 CPU 端 gloo group 作为 suspend/resume 期间跨 rank barrier 通道，保留GPU 不可用时的同步能力（为后续 checkpoint 的持久化提供技术基础）。

E/PD 分离（视觉推理结果持久化跨节点/请求复用）

阿里控股-智能引擎 · AI infra-大模型推理优化实习生 · 2026.06 - 至今

  1. 针对离线推理场景的多模态推理中E编码与PD解码耦合、E推理阶段 CPU bound 严重导致GPU利用率低下、E推理的结果无法多实例复用导致算力浪费的问题 ，设计了 E/PD 分离的解决方案。
  2. 设计并实现 vision_cache 的计算与命中机制：以 h128(model, url, dtype，tokenizer) 为 key 进行 缓存 fingerprint 计算；E 阶段异步D2H 上传（有界队列背压、幂等重传）；PD 阶段 同步 H2D 下载
  3. E 阶段 仅加载视觉部分权重节约显存98%，计算 128 位哈希用于fingerprint，根据 哈希值 向 存储backend 点查是否存在已计算的 vision_cache，如果 缓存命中 则 复用缓存 跳过 URL 下载 与 视觉推理 节约网络IO与算力，接受下一个请求；如果缓存未命中则 依次进行 下载+预处理+视觉推理+向存储的 backend 提交推理结果供多请求复用。
  4. PD 阶段 接受与 E 阶段完全相同的请求，计算哈希，cache 命中则复用vision cache，未命中返回错误码保持引擎存活；若命中则复用 cache 存储的 tensor 跳过 URL+预处理+E推理 节约网络 IO 与 算力。
  5. 针对生产环境的问题持续迭代优化：
    1. 多 TP 场景 选举 rank0 拉取云端 tensor + broadcast 分发，降低通信压力与数据库点查压力
    2. E阶段 LM 权重拒绝加载、极大降低显存占用，E阶段与PD 阶段完全解耦，提高低算力卡的利用率

  2. 基于CUDA在八卡H20上实现 MoE Token 分发（Dispatch）和结果归约（Reduce）模块的 CUDA 实现。
    1. 在Dispatch 阶段使用 atomicAdd 统计每个 rank 上每个 Expert 的 Token 数量，用 CUB BlockScan计算 前缀和 获取起始位置，将数据在显存中聚合成为连续内存，在 Group_gemm 阶段 保证 TMA 保持高效数据搬运；
    2. 在Reduce阶段，使用Shared Memory 暂存映射表和权重，完成 topk 加权归约。相比baseline提高1.42倍
  3. 基于triton 开发 Linear attention 模块中 的反向传播算子，实际测试中发现反向传播中两部分计算的瓶颈不同，将反向传播设计为两个stage。
    1. Stage 1计算需要全局归约的梯度 进行 dQ/dH/dZ 的计算，遍历 Q、K 维度，计算局部梯度用 atomic_add 聚合；
    2. Stage 2 计算 dK/dV 无需全局聚合，但是需要Stage1计算数据的梯度。Stage1采用 autotune 进行自动调优，Stage2使用 Persistent kernel 充分利用多SM资源。相比 pytorch 原生实现的 baseline 提高2倍。
